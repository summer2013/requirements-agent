# 需求智能体 — Claude Projects 使用指南

---

## 一、初始化（只做一次）

### 1. 新建 Project

打开 claude.ai → 左侧点击 **New Project** → 命名为「需求智能体」。

### 2. 上传三个提示词文件

进入 Project → 点击右上角 **Add content** → **Upload files**，上传：

```
prompts/projects/research_system.txt
prompts/projects/document_system.txt     ← v2 已升级
prompts/projects/prototype_system.txt    ← v2 已升级
```

### 3. 粘贴 Project Instructions

点击 **Set project instructions**，将以下内容完整粘贴进去：

---

```
你是一个需求阶段智能体，负责引导用户完成：
需求调研 → PRD 文档 → PRD 评审 → HTML 原型
四个阶段。每个阶段结束后必须暂停，等待用户确认再继续。

════════════════════════════════
启动规则
════════════════════════════════
每次新对话开始时，无论用户说什么，
你的第一句话必须是：

"你好！在开始之前，请告诉我：
1. 项目名称是什么？
2. 用一段话描述项目背景、目标用户和核心问题。"

在用户回答这两个问题之前，不做任何其他事情。

════════════════════════════════
阶段一：需求调研
════════════════════════════════
收到项目信息后，读取 research_system.txt 文件，
严格按照其中的框架进行访谈。

访谈结束后，输出完整 JSON 格式的访谈笔记，并告知用户：
"请复制以上 JSON，保存为 interview_notes_项目名.json，
上传到 Project 文件区供下一阶段使用。"

────────────────────────────────
⏸ 人工检查点 ①
────────────────────────────────
输出访谈笔记后，询问用户：
"以上访谈笔记是否完整准确？
- 如有遗漏请告知，我来补充追问
- 确认无误请回复：确认，进入阶段二"

在用户明确确认前，不进入下一阶段。

════════════════════════════════
阶段二：PRD 文档
════════════════════════════════
收到「确认，进入阶段二」后：
1. 读取 document_system.txt 文件了解 PRD 规范
2. 优先读取用户上传的 interview_notes_*.json 文件
   如无上传文件，使用当前对话中的访谈笔记内容
3. 生成完整 PRD，直接输出 Markdown 内容
   PRD 必须包含：状态机章节（核心业务对象的所有状态）
4. 输出完毕告知用户：
   "请复制以上内容，保存为 prd_项目名.md，
   上传到 Project 文件区。"

════════════════════════════════
阶段 2.5：PRD 系统评审（自动运行）
════════════════════════════════
PRD 输出完毕后，无需用户触发，立即对 PRD 进行五维度评审：

1. 结构完整性：背景/目标/角色/Out of Scope/异常处理是否齐全
2. 逻辑一致性：每条用户故事是否写明了前提条件和操作后的状态变化
3. 流程闭环：每个流程是否有明确出口，是否存在用户无法退出的死路
4. 场景穷举（MECE）：
   - 列表页是否描述了空状态
   - 表单页是否描述了校验错误处理
   - 异步操作是否描述了等待/失败状态
   - 不可逆操作是否有二次确认机制
   - 并发/中途退出的处理是否有描述
5. 多角色协同：跨角色流程的通知时机、等待态、超时处理是否定义

评审结果按 critical / major / minor 三级列出，格式示例：

[CRITICAL] 结构完整性 | 缺少 Out of Scope 声明 → 建议补充第 2 章范围说明
[MAJOR] 场景穷举 | 订单列表页未描述空状态 → 建议补充"暂无订单"的展示和引导操作
[MINOR] 逻辑一致性 | US-004 未说明操作后页面跳转逻辑 → 建议补充"提交后跳回列表页"

────────────────────────────────
⏸ 人工检查点 ②
────────────────────────────────
输出 PRD + 评审报告后，询问用户：
"以上是 PRD 文档和系统评审结果。
- 如需修订 PRD，请告知具体问题（评审发现的问题会一并修复）
- 确认无误请回复：确认，进入阶段三"

重要：如果评审发现 critical 级别问题，在用户确认前主动建议先修订 PRD。
在用户明确确认前，不进入下一阶段。

════════════════════════════════
阶段三：HTML 原型
════════════════════════════════
收到「确认，进入阶段三」后：
1. 读取 prototype_system.txt 文件了解原型规范
2. 优先读取用户上传的 prd_*.md 文件
   如无上传文件，使用当前对话中的 PRD 内容
3. 按以下顺序生成原型（顺序不能颠倒）：
   a. 先梳理信息架构（列出所有页面 + 每页的入口/出口）
   b. 再确认流程无死路（每个分支都有出口）
   c. 最后生成 HTML，必须覆盖评审发现的所有 missing_scenarios
4. 生成完毕前，对每个页面逐一自检：
   - 是否有空状态（列表页）
   - 是否有操作反馈（成功/失败提示）
   - 不可逆操作是否有确认弹窗
5. 自检通过后输出完整单文件 HTML，并告知用户：
   "请复制以上全部代码，新建文本文件，
   粘贴后另存为 prototype_项目名.html，
   用浏览器打开即可预览。"
```

---

初始化完成，Project 文件区：

```
需求智能体 Project
├── Instructions（上方内容）
├── research_system.txt
├── document_system.txt
└── prototype_system.txt
```

## 二、运行一个项目

### 第一步：开启新对话

进入 Project → 点击 **New conversation**（每个项目必须开新对话）。

Claude 自动询问项目名称和简介，输入后访谈开始。

### 第二步：完成访谈（阶段一）

按 Claude 的提问逐条回答，5-7 轮后 Claude 输出 JSON 访谈笔记。

**检查点 ①**
- 有遗漏 → 告知补充内容
- 确认 → 回复「确认，进入阶段二」

**保存笔记**：复制 JSON → 保存为 `interview_notes_项目名.json` → 上传到 Project。

### 第三步：生成 PRD + 自动评审（阶段二 + 阶段 2.5）

Claude 读取访谈笔记生成 PRD，完成后**自动运行 PRD 评审**，输出评审报告。

**如何看评审报告**
- `[CRITICAL]` — 必须修订，否则产品无法正常运行
- `[MAJOR]` — 原型阶段前需要修复的场景遗漏或逻辑问题
- `[MINOR]` — 体验细节，可在后续迭代处理

**检查点 ②**
- 有 critical 问题 → 建议先修订 PRD，告知具体意见
- 确认 → 回复「确认，进入阶段三」

**保存 PRD**：复制 Markdown → 保存为 `prd_项目名.md` → 上传到 Project。

### 第四步：生成原型（阶段三）

Claude 先列出信息架构和页面清单，确认流程无死路，再输出完整 HTML 代码。
原型会覆盖评审报告中发现的所有遗漏场景。

**保存原型**：复制全部代码 → 另存为 `prototype_项目名.html` → 浏览器打开预览。

### 第五步：复盘沉淀

开一个新对话，输入：

```
请根据已上传的 interview_notes_项目名.json 和 prd_项目名.md 做项目复盘。

分析：
1. PRD 中出现但访谈未明确覆盖的需求有哪些？
2. 下次做类似项目，访谈时应主动问哪些问题？
3. 提炼 3-5 条可操作的经验教训。

输出 JSON 格式：
{
  "lessons_learned": [...],
  "missed_requirements": [...],
  "interview_tips": [...]
}
```

复制输出 → 保存为 `review_项目名.json` → 上传到 Project。

## 三、Project 文件区全貌

```
需求智能体 Project
│
├── 【固定文件，初始化时上传，不需要改】
│   ├── research_system.txt
│   ├── document_system.txt           ← v2 已升级
│   └── prototype_system.txt          ← v2 已升级
│
└── 【积累文件，每个项目结束后上传】
    ├── interview_notes_商品更新平台.json
    ├── prd_商品更新平台.md
    ├── review_商品更新平台.json
    ├── interview_notes_供应链平台.json
    ├── prd_供应链平台.md
    ├── review_供应链平台.json
    └── ...（越积越多，Claude 参考经验越丰富）
```

注意：每个 Project 最多上传 20 个文件。积累超过 15 个项目后，
可以把早期的 `prd_*.md` 删掉，只保留 `interview_notes_*.json` 和 `review_*.json`，
这两类文件信息密度更高。

## 四、常用触发语

| 场景 | 说什么 |
|------|--------|
| 通过检查点① | `确认，进入阶段二` |
| 通过检查点② | `确认，进入阶段三` |
| 补充访谈 | `缺少对XX角色的访谈，请补充` |
| 修订 PRD（含评审问题） | `请修复评审中的所有 critical 和 major 问题，并重新输出 PRD` |
| 修订 PRD（特定问题） | `US-003 验收标准太模糊，请补充错误场景` |
| 跳过访谈直接生成 PRD | `跳过访谈，读取已上传的 interview_notes_项目名.json 生成 PRD` |
| 跳过 PRD 直接生成原型 | `跳过阶段二，读取已上传的 prd_项目名.md 生成原型` |
| 做复盘 | `根据已上传的访谈笔记和 PRD 做项目复盘，输出 JSON` |

## 五、优化路径

### 现在：调优提示词

每次发现 Claude 的行为有问题，直接修改 `prompts/projects/` 下对应的 `.txt` 文件，
重新上传替换旧版本。

| 问题现象 | 修改文件 | 修改方向 |
|---------|---------|---------| 
| 访谈问题太机械 | research_system.txt | 在"绝对不做的事"加反例 |
| 某类项目总遗漏某需求 | research_system.txt | 在对应类型"特别注意"里补充 |
| PRD 用户故事太模糊 | document_system.txt | 在"常见错误"加新反例 |
| 评审总是漏报某类问题 | Project Instructions（阶段 2.5 部分） | 在"场景穷举"检查项里补充 |
| 原型缺少某类页面 | prototype_system.txt | 在"必须包含的页面"补充 |
| 原型某类状态总是空白 | prototype_system.txt | 在"状态完整性要求"里加说明 |

### 积累 5 个项目后：建索引文件

新建 `knowledge_base_index.md` 上传到 Project：

```markdown
# 知识库索引

## 零售 / 电商
- interview_notes_商品更新平台.json（运营工具，Saleor集成）
  关键经验：涉及外部系统必问 API 批量能力

## 内部工具
- interview_notes_审批流系统.json（HR流程）
  关键经验：单人运营项目注意单点风险

## 高频遗漏场景（来自 PRD 评审）
- 所有 B 端项目：审计日志 / 操作记录容易被遗漏
- 涉及审批流：超时自动处理逻辑经常缺失
- 涉及导出功能：大数据量导出的异步处理经常未描述
```

新项目开始时告诉 Claude：「请先读取 knowledge_base_index.md，找到最相关的历史参考，
并在访谈中主动关注高频遗漏场景。」

### 需要自动化时：升级 API 方案

出现以下情况时升级：
- 每周需要跑 3 个以上项目
- 需要多人共享知识库
- 需要自动接入 Jira / Confluence / 飞书
- 需要 PRD 评审报告自动存档（API 方案输出 `prd_review_report.json`）

参考 `README.md` 的 API 方案快速开始。

## 六、常见问题

**Q：Claude 没有先问项目信息，直接开始了？**
Project Instructions 未生效。重新进入 Project → 确认 Instructions 已保存 → 开新对话。

**Q：阶段 2.5 评审没有自动运行，Claude 直接问要不要进入阶段三？**
Project Instructions 里阶段 2.5 的内容可能未被 Claude 读到。
手动触发：「请先对以上 PRD 进行五维度评审，输出 critical / major / minor 分级问题清单，再询问我是否确认。」

**Q：消息条数用完了，项目没跑完怎么办？**
等 5 小时重置后开新对话，输入：
「继续项目：项目名。已完成阶段一，访谈笔记已上传，请从阶段二开始。」

**Q：Claude 输出的不是 JSON 格式怎么办？**
补充一句：「请将访谈笔记整理成 JSON 格式输出，字段包括：
user_roles、pain_points、requirements、success_metrics、open_questions、summary、confidence_level。」

**Q：Project 文件超过 20 个怎么办？**
删除早期项目的 `prd_*.md`（内容已被 `interview_notes_*.json` 覆盖），
只保留访谈笔记和复盘文件，信息密度更高。

**Q：上传的文件会被 Anthropic 用于训练模型吗？**
在 claude.ai 设置 → Privacy → 关闭「Allow Claude to train on my conversations」即可。
